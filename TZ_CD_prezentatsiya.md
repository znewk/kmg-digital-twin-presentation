# ТЗ: Интерактивная 3D-презентация «Цифровой двойник месторождения»
### КазМунайГаз · пилот Молдабек Восточный · показ для Президента РК и МЭПМ

---

## 0. Контекст и цель

Компания КМГ внедряет программу «Цифровой двойник» (вендор — Nedra Digital, платформа
строится вокруг существующей ИС «ABAI» как учётного ядра). Пилотный актив — месторождение
Молдабек Восточный (АО «Эмбамунайгаз»). Требуется интерактивная веб-презентация уровня
демонстрации **Президенту Республики Казахстан и МЭПМ** — то есть максимальный визуальный
и технический уровень исполнения, без права на «сыровато» или «шаблонно».

Формат — скролл-управляемая 3D/2D презентация в браузере (референс жанра —
`superkelov.github.io/orbital-presentation`, cinematic scroll-driven site), сочетающая:
- физически убедительную 3D-визуализацию месторождения (недра, скважины, наземная инфраструктура);
- стилизованные 2D-панели реальных программных модулей (NUMEX, RTM, WWO, Digital Twin,
  INFRAPLAN, NDP), в которые презентация «проваливается» по сценарию;
- плавную скролл-навигацию с остановками на этапах и полной кликабельностью объектов.

**Ключевой прецедент, который нужно ПРЕВЗОЙТИ по чистоте архитектуры и визуалу, но
сохранить как основу идей**: приложенный файл `ЦД_месторождение_3D_v3.html` — рабочий
одностраничный прототип на vanilla Three.js (r160), сделанный другим агентом по смежному
брифу. Он НЕ идеален (монолитный файл на 2500+ строк, тормозит на слабом железе,
визуально «несуразный» по итоговой оценке владельца продукта), но в нём заложена
правильная архитектурная логика, которую нужно **переиспользовать и довести до полного
качества**, переписав на нормальный современный стек.

## 1. Что конкретно хорошо в референсном HTML-прототипе — переиспользовать идеи

Изучите `ЦД_месторождение_3D_v3.html` целиком перед стартом. Конкретные паттерны, которые
работают и должны быть сохранены (в переработанном виде):

- **Процедурная геология**: недра строятся не статичным мешем, а функциями шума
  (`fbm(x,z)`) + структурная кровля с антиклиналью (`dome(x,z)`) + сброс со смещением
  (`faultTraceX`, `throwAt`) — это даёт реалистичный, не «игрушечный» разрез. Слои
  (`stratumGroup`, `addLayer`) генерируются программно с прозрачностью и цветом.
- **Скважины по CatmullRom-кривым** с обсадной/НКТ/перфорацией, разные типы (ШГН с
  качалкой, ЭЦН с кабелем, горизонтальная, ГРП с трещиной, нагнетательные, буровая с
  талевым блоком/ротором/долотом, ТКРС с агрегатом) — не примитивная геометрия, а
  собранные из детализированных частей объекты.
- **Система камер** — словарь именованных ракурсов `CAMS = { overview, section,
  reservoir, flood, wellbore, rig, workover, surface, pipes, plant, power, chain }` с
  функцией `flyTo(name, dur)` и easing (`easeInOutCubic`), плюс привязка `TWIN_CAM` —
  каждый «контур» (пласт/скважина/добыча) имеет свой базовый ракурс. **Этот принцип
  сохранить один в один**, просто перенести управление на скролл-таймлайн вместо ручного
  вызова.
- **Панель процессов** (`buildPanel`) — при выборе контура показывается пронумерованный
  список процессов с описанием и бейджами покрытия по системам (ABAI/NEDRA/вендор),
  клик по процессу → `flyTo(p.cam)` + подсветка связанных объектов (`linkedSet`).
  Двусторонняя связь объект↔процесс.
- **CSS2D-подписи** (`CSS2DRenderer`/`CSS2DObject`) — подписи объектов в 3D-пространстве,
  плюс отдельный слой `sysLabel` для плашек модулей ПО прямо над объектами во время показа.
- **OutlinePass** — обводка объекта в фокусе (постпроцессинг), а не просто изменение
  цвета материала — даёт киношный акцент.
- **Разрез через clippingPlanes** — ползунок, срезающий верхнюю часть недр для обзора
  внутренней структуры, без пересборки геометрии.
- **Легенда систем с покрытием**: `coveredCount(src)` считает, сколько из 20 процессов
  закрывает каждый источник (ABAI/NEDRA/вендор), выводится как «закрывает N из 20» —
  обязательно сохранить эту механику, она была отдельно затребована владельцем продукта.
- **Автодеградация качества по FPS**: `perfSample(dt)` + `degradeQuality()` — первые ~3
  секунды измеряется FPS, при просадке ниже порога отключаются bloom/тени/OutlinePass и
  снижается pixelRatio. **Обязательно перенести этот принцип**, показ будет идти на
  неизвестном по мощности железе.
- **Автопоказ**: intro → главы с титульными плашками → финальный chain, кликер
  (стрелки/Space/Esc/F), автопилот с паузой по вмешательству мыши. Раскладка клавиш должна
  работать и в русской (`А`=фулскрин и т.п.), это уже было реализовано — сохранить.

## 2. Что делать принципиально ИНАЧЕ (претензии владельца продукта к текущему виду)

- **Монолитный vanilla-JS файл на 2500+ строк — неприемлем** для дальнейшего сопровождения
  и итераций. Переписать на **React + React Three Fiber (R3F)**, декомпозировать сцену на
  компоненты (`<EarthLayers/>`, `<Well type="esp"/>`, `<Pumpjack/>`, `<SurfaceFacility
  id="tsppn-kenbay"/>` и т.д.), стейт — через Zustand.
- **Визуальное качество «несуразное»** — это оценочная, не техническая претензия; нужно
  применить дизайн-дисциплину: единая цветовая температура, вменяемые пропорции объектов
  (в правках черновика уже было замечание «слишком мелко/крупно» — решать через
  осознанный масштаб, а не догадками), настоящий bloom-постпроцессинг (`UnrealBloomPass`),
  качественные материалы (PBR, а не плоские `MeshBasicMaterial` везде).
  Перед кодом — обязательна фаза дизайн-брифа (палитра, типографика, референсы) по
  методологии `frontend-design`, а не сразу вёрстка.
- **Скролл вместо ручного клика/автопилота как основной режим навигации.** Сейчас в
  прототипе интеракция — это клик по процессу или кнопки автопоказа. Требуется
  **scroll-driven timeline (GSAP ScrollTrigger)**: скролл вниз/вверх плавно и **реверсивно**
  двигает камеру и разворачивает анимации по этапам сценария, с возможностью
  «застревания»/паузы на этапе для детального клика по объектам. Кнопочный/кликер-режим
  можно оставить как фолбэк-альтернативу для показа с пульта, но основной UX — скролл.
- **Процедурная («выдуманная») геометрия площадки заменяется реальной.** В прототипе
  рельеф генерируется шумом `fbm(x,z)`, а кусты/трубы/объекты расставлены произвольно «по
  композиции». Теперь есть фактические геоданные исполнительной съёмки (см. §4.1) —
  рельеф, 570 скважин, 188 кустов, реальные трассы сетей. Прототип берётся за основу
  **как библиотека 3D-объектов и приёмов** (как выглядит качалка, буровая, ГЗУ, РВС,
  факел, как анимируется поток в трубе), но **раскладка сцены полностью переносится на
  реальные координаты**. Процедурная геология НЕДР (антиклиналь, сброс, слои) при этом
  сохраняется — подземная часть не покрыта топосъёмкой и остаётся условно-модельной, но
  должна быть согласована с поверхностью по координатам.
- **Производительность за счёт гибридного 2D/3D**, а не только деградации качества:
  тяжёлые сцены наземной инфраструктуры/обвязки труб — рассмотреть baked-текстуры/
  инстансинг вместо количества полигонов «в лоб» (в прототипе уже частично сделано через
  `instancedBars`, но применить шире).

### 3.1 Открывающая гео-последовательность (детализация блоков 1–3, ОБЯЗАТЕЛЬНА)

Вместо статичного «титульного 2D-экрана» на блоках 1–2 — непрерывный кинематографичный
zoom-in по скроллу, физически переносящий зрителя от макро-уровня к месторождению.
Порядок этапов (каждый — остановка скролл-таймлайна):

1. **Планета** — стилизованный вращающийся глобус Земли в тёмном космосе (перекликается
   с референсом «ЦД Актива» — тёмный космический фон с глобусом, см. §6, последний пункт).
   Решить на этапе прототипирования: либо полноценный глобус Земли с переходом камеры к
   Казахстану, либо сразу открывать картой Казахстана без глобуса — что даст более чистый
   и быстрый вход без лишнего хронометража (показ ограничен по времени, см. §3).
2. **Карта Казахстана** — контуры областей, на карте подсвечиваются **все 12 приоритетных
   активов программы**. Официальная формулировка из презентации АТК (слайд 11):
   «Развёртывание на **12 приоритетных активах 7 ДЗО**», сроки — 2027–2028 гг.,
   охват ≈ 87 % запасов и ≈ 90 % добычи КМГ. Требования к отображению:
   - все 12 активов показаны маркерами по стране, с названиями;
   - **пилот (Восточный Молдабек) визуально выделен** среди остальных — иной цвет/размер/
     свечение + подпись статуса «пилот · запуск в промышленную эксплуатацию — октябрь
     2026», остальные 11 помечаются как «тиражирование 2027–2028»;
   - при желании — группировка маркеров по ДЗО (7 дочерних организаций).

   **Поимённый список 12 активов в открытых источниках не публикуется и во внутренних
   материалах, переданных для этой задачи, не раскрыт.** Его необходимо получить у
   заказчика (КМГ Инжиниринг / ДЦР) до финальной сборки. До получения — работать по
   структуре «7 ДЗО × их ключевые месторождения»; наиболее вероятный состав (ТРЕБУЕТ
   ПОДТВЕРЖДЕНИЯ, НЕ ВЫДАВАТЬ ЗА ФАКТ):

   | ДЗО | Вероятные активы |
   |---|---|
   | АО «Эмбамунайгаз» | **Восточный Молдабек (пилот)**, Прорва, Кенбай |
   | АО «Озенмунайгаз» | Узень, Карамандыбас |
   | АО «Мангистаумунайгаз» | Каламкас, Жетыбай |
   | АО «Каражанбасмунай» | Каражанбас |
   | ТОО «Казгермунай» | Акшабулак, Нуралы/Аксай |
   | ПетроКазахстан (ПККР) | Кумколь |
   | ТОО «Казахойл Актобе» | Алибекмола, Кожасай |

   Если к моменту сборки точный список не получен — предусмотреть, чтобы список активов
   задавался **данными (конфигом), а не хардкодом**, и заменялся одной правкой.
3. **Атырауская область** — call-out: подсветка/укрупнение Атырауской области, остальные
   области затемняются/уходят на второй план.
4. **Погружение к месторождению** — продолжение zoom прямо к площадке Молдабек Восточный.
   **Точные координаты пилота, вычисленные из исполнительной съёмки (см. §4.1):**
   центр площадки — **47.7373° с.ш., 54.1449° в.д.** (Атырауская область,
   Кызылкогинский район). Исходная проекция чертежа — **UTM зона 40N (EPSG:32640)**.
   Это позволяет сделать зум с карты на площадку геометрически корректным и бесшовным:
   карта страны → область → реальные границы промысла из геоданных.
5. **РЕАЛЬНАЯ СХЕМА МЕСТОРОЖДЕНИЯ (2D, плоский вид сверху)** — ключевой новый этап.
   Строится на **фактических геоданных из исполнительного топоплана** (см. §4.1):
   570 реальных скважин на своих координатах, 188 узлов сбора (кусты), реальные трассы
   нефтесбора/водоводов/газопровода, ВЛ-10 кВ и 0,4 кВ, ГЗУ, резервуарный парк, факел,
   здания, дороги, горизонтали рельефа. Это «фотография» настоящего промысла, а не схема
   из презентации. Объекты кликабельны уже на этом плоском виде.
   Поверх реальной геометрии могут накладываться смысловые обозначения из `image4.png`
   (МФНС / СП «В-Молдабек» / ЦППН «Кенбай» / КНС / БРХ / ПС — см. §4) — но привязанные к
   их фактическому положению на плане, а не к произвольной схеме.
6. **Падение в полную 3D-модель месторождения** — переход от плоской реальной схемы к
   объёмной сцене. **3D-модель обязана быть узнаваемым продолжением того же плана**:
   те же кусты на тех же местах, те же трассы труб, тот же рельеф — просто теперь
   объёмные, с недрами под поверхностью и оборудованием на площадках. Переход
   плоскость → объём должен читаться как «карта поднимается в 3D», а не как подмена
   одной картинки другой. С этого момента начинается детальная 3D-часть презентации
   (§1, §2, §8.3), соответствующая блокам 3–6 сценария.

Это заменяет прежнее упрощённое описание блоков 1–2 как «2D титульный/архитектурный
экран» — теперь это единая непрерывная последовательность погружения, а не отдельный
статичный слайд.

## 4. Точная карта реальных объектов месторождения (обязательна для 3D и 2D-карты)

Из `image4.png` вложения (кликабельная карта UPSTREAM, вариант 2 сценария) — реальная
топология пилота, использовать точные названия и связи:

```
Нефтяной фонд (несколько кустов, разные типы скважин: ШГН, ЭЦН, ГС)
    → МФНС (многофазная насосная станция)
    → СП «В-Молдабек» (сепараторы на опорах, узел замера)
    → напорный нефтепровод
    → ЦППН «Кенбай» (техблоки, колонна, теплообменники, 4×РВС, факел)
Скважина ППД → КНС (кустовая насосная станция)
БРХ (блок реагентного хозяйства) — реагентные линии к точкам подачи
ВЛ (12 опор, провисающие провода) — от ПС к кустам
ПС (подстанция)
```

Модули привязаны к объектам конкретно (см. `image4.png` для точной раскладки бейджей):
модуль «Подбор ГНО» и «Онлайн мониторинг бурения» — на нефтяном фонде; «Гидравлические
расчёты» и «Трубопроводы» — на магистрали; «Химизация» — на БРХ; «Энергетика» — на ВЛ/ПС;
«Предиктивный анализ отказов оборудования» — на напорном трубопроводе; «КНС и ППД» и
«Предиктивный анализ» — на скважине ППД/КНС.

## 4.1. РЕАЛЬНЫЕ ГЕОДАННЫЕ МЕСТОРОЖДЕНИЯ — основа и 2D-схемы, и 3D-модели

**Это важнейшее требование проекта: презентация должна быть настоящим цифровым двойником,
а не художественной иллюстрацией.** Заказчиком предоставлен исполнительный топографический
план `В_Молдабек_2023_М2000.dwg` (AutoCAD Civil 3D, масштаб 1:2000, съёмка 2023 г.,
152 776 объектов, 86 слоёв). Из него извлечён и оптимизирован для веба датасет — файлы
прилагаются:

- **`moldabek_field_data.json`** (294 КБ) — полный: рельеф + все сети + скважины
- **`moldabek_field_light.json`** (152 КБ) — облегчённый: без сетки рельефа и горизонталей

### Промысловые объекты с реальными названиями (`facilities`)

Из чертежа извлечены фактические обозначения — это снимает необходимость угадывать
семантику по геометрии:

- **41 × ГЗУ** — групповые замерные установки с номерами: ГЗУ-1 … ГЗУ-52, включая
  спаренные (ГЗУ-28/29, ГЗУ-35/36, ГЗУ-37/38). Это и есть центры кустов.
- **3 × КНС** — кустовые насосные станции ППД: **КНС-2, КНС-3, КНС-4**.
- **3 × СП** — сборные пункты: **«СП Молдабек»** (координаты `[4221.8, 2415.1]` — совпадает
  с восточным комплексом, рядом с факелом `[4156, 2462]`), **СП-16**, **«Мини СП N43»**.
- **10 × КТП/ТП** — комплектные трансформаторные подстанции (КТП-202, КТП209 и др.).

**Вывод по семантике:** восточный комплекс — это **СП «Молдабек»** (сборный пункт), что
согласуется с наименованием «СП В-Молдабек» из `image4.png` сценария. ЦППН «Кенбай»
находится **за пределами данного топоплана** (это отдельная площадка подготовки нефти),
поэтому на 2D-схеме и в 3D его следует показывать как внешний узел — например, стрелкой/
выносом «напорный нефтепровод → ЦППН «Кенбай»» за границу участка, а не выдумывать ему
место внутри плана. Аналогично МФНС и БРХ в подписях чертежа отсутствуют — если они не
находятся в границах съёмки, их также обозначать как внешние/условные узлы с явной
пометкой, а не привязывать наугад к произвольному зданию.

Геометрия уже прошла слияние фрагментов и упрощение (Douglas–Peucker), дубликаты
символов скважин кластеризованы (3 203 → 570). Мелочь (тротуары, деревья, фонари,
текстовые отметки высот, коды, откосы) намеренно отброшена.

### Как это обязано использоваться

1. **2D-схема месторождения** (§3.1, п.5) рисуется напрямую из этого JSON — реальные
   позиции, реальные трассы, реальные номера скважин.
2. **Рельеф в 3D-сцене строится из `terrain.grid`**, а НЕ процедурным fbm-шумом, как в
   референсном HTML-прототипе. Функцию `fbm()` из прототипа заменить на выборку из
   реальной высотной сетки. Перепад высот на участке — около 40 м, при визуализации
   допустимо умеренное вертикальное преувеличение для выразительности, но пропорции
   должны оставаться правдоподобными.
3. **Кусты скважин и трассы труб в 3D размещаются по фактическим координатам** из
   `hubs`/`wells`/`networks`, а не «на глаз». Детализированные 3D-модели оборудования
   (качалки, ГЗУ, резервуары, факел) ставятся в реальные точки.
4. **Номера скважин — настоящие** (`wells[].n`), не выдуманные.
5. Для 3D допустима разумная генерализация: не обязательно выводить все 570 скважин
   отдельными детализированными моделями (это убьёт производительность) — ближние к
   камере кусты детализированные, дальние — упрощённые/инстансированные маркеры
   (LOD-подход, `InstancedMesh`). Но **топология и позиции должны соответствовать
   реальности**.

## 7. Реальное состояние ABAI — ограничения точности (обязательно учесть в контенте!)

Подтверждено владельцем продукта (представитель КМГИ), актуально на начало августа 2026:

1. Модуль **ЦБ (Цифровое бурение)** в ABAI — **не функционирует**, не используется в
   продакшене.
2. Модуль **ТКРС** в ABAI — **не функционирует** (восстановление в плане до конца года).
3. **Интеграции с Департаментом ИИ отсутствуют** — AI-агенты в архитектуре ЦД Актива
   (см. §3, блок 8) — это **целевой/перспективный слой**, не факт сегодняшнего дня.
   Помечать в UI соответствующе (например, бейдж «целевой контур» вместо «активно»).
4. **Наземная инфраструктура в ABAI** — только векторные карты объектов, без
   мониторинга/анализа. Это обоснование, зачем нужен отдельный INFRAPLAN.
5. **ЭМГ реально имеет доступ только к модулям ABAI**: БД, КП (Картопостроитель), ТР
   (Технологический режим), ПДИМ, ПАЭГТМ, ПГНО. Модули **ЦРНС** и **УЗ (Управление
   заводнением)** — НЕ входят в текущий доступ ЭМГ (есть у ММГ/ОМГ и др. ДЗО). В
   сценарии блок 3 показывает эти модули для Молдабек В. как **донасыщение/новое
   внедрение**, не как существующий факт — обязательно промаркировать в UI (например,
   бейдж «новое для ЭМГ»), чтобы не ввести в заблуждение техническую аудиторию (МЭПМ).
6. Источник данных для наполнения — DEV-база ABAI, актуальна на начало августа 2026 —
   если будут использованы реальные цифры, помечать как DEV-контур.

### 8.1 Палитра (наследуется от HTML-прототипа, за основу)
```css
--bg0: #050810;       /* фон, глубокий космос/недра */
--bg1: #0C1626;
--c-plast: #F0AE4A;   /* пласт — янтарь */
--c-skv: #8FBAF0;     /* скважина — голубой */
--c-dob: #35D0C2;     /* добыча — бирюза */
--c-abai: #4EA3F0;    /* ABAI — синий */
--c-nedra: #9B7BE8;   /* Nedra — фиолетовый */
--glass: rgba(10,18,32,.8);
--txt: #D7E2F2; --txt-dim: #7C8DA6;
```
Все 2D-панели модулей (реально светлые/разноцветные в оригинале, см. §6) стилизуются под
эту тёмную палитру для визуальной цельности — не копировать исходные светлые темы 1:1.

### 8.2 Приветственный экран — «витрина месторождения»
Утверждённая концепция (см. приложенный `field_showcase_hero.jsx` — рабочий прототип на
Three.js, черновая реализация идеи, использовать как отправную точку геометрии, НЕ как
финальное визуальное качество):
- Цилиндрический «срез земли» как драгоценный экспонат на подиуме — 6 геологических
  слоёв (янтарь→синий), лёгкая антиклиналь.
- Светящаяся траектория скважины сквозь слои, полупрозрачная плоскость ВНК.
- Одна деталь оборудования крупным планом на поверхности блока (качалка с покачиванием
  балансира, либо буровая вышка — решить по итоговой компоновке).
- Лёгкое облако частиц вокруг (данные).
- **Вращение объекта строго синхронизировано со скроллом (реверсивно)** — не автономная
  анимация: `rotation.y` объекта = функция от scroll progress, через GSAP ScrollTrigger
  `scrub: true`. Никакого предрендеренного видео для этого конкретного экрана — экран
  первый, лёгкий, полностью потянет live-3D.
- Никакого интерфейса/подписей/интерактива на этом экране — чистый атмосферный вход.

### 8.3 Клик и детализация объектов — переход к 3D-модели объекта, не просто панель

Каждый геологический слой, скважина (и её узлы — устье, ГНО, перфорация), линия
заводнения, каждый объект наземной инфраструктуры — кликабельны (raycasting в R3F,
`onClick`). Это касается и объектов, появляющихся при раскрытии каждого из контуров ЦД
(Пласт / Скважина / Добыча и наземная инфраструктура / Ресурсной базы) — при выборе
контура его объекты становятся доступны для клика по отдельности.

**Важное уточнение поведения при клике (отличается от HTML-прототипа, где клик по
процессу в панели просто переключал общий ракурс контура):**
1. Камера **прицельно приближается к конкретному 3D-объекту** (индивидуальный ракурс
   именно этой скважины/установки, а не общий ракурс контура «wellbore»/«surface» — то
   есть система камер `CAMS` должна поддерживать не только именованные общие ракурсы, но
   и динамически вычисляемые ракурсы под конкретный инстанс объекта).
2. Зритель видит **сам детализированный 3D-объект крупным планом** (например, конкретную
   качалку со всеми узлами, а не абстрактную панель поверх сцены).
3. Поверх/рядом с приближенным 3D-объектом появляется **info-панель с параметрами**: тип
   объекта, ключевые данные (для скважины — дебит, обводнённость, давление, температура;
   для пласта — пористость/проницаемость/насыщенность; для наземного объекта — параметры
   по функционалу привязанного модуля), привязанный модуль `Nedra.*`/ABAI (§5, §7), и,
   где уместно по сценарию, прогнозные значения.
Панель **дополняет** приближенный 3D-вид объекта, а не заменяет его плоским скриншотом-
подобием интерфейса — 3D-модель объекта остаётся видна и в фокусе на протяжении показа
его деталей.

### 8.4 Полнота набора объектов (обязательное требование)

Все элементы, присутствующие в HTML-прототипе, должны быть перенесены/улучшены, НЕ
урезаны: все 8 типов стволов (ШГН, ЭЦН, горизонтальная, ГРП, 2× нагнетательные, буровая,
ТКРС), вся наземная обвязка (кусты с обваловкой, МФНС, СП, ЦППН со всеми техблоками/РВС/
факелом, БРХ, КНС, ВЛ на опорах с провисающими проводами, ПС, ЦИО), сетка ГДМ,
сейсмопрофиль, зоны дренирования, фронт заводнения, конус обводнения, res-map
изолиниями. Каждый элемент — кликабелен (§8.3) и анимирован там, где это заложено в
прототипе (покачивание балансира качалки, вращение ротора буровой, бегущий поток в
трубах, дым факела, движение цистерны/вахтовки по кольцу, импульсы телеметрии на мачте
ЦИО) — с сохранением или улучшением качества анимации, не деградацией.

## 9. Технологический стек

```
React 18 + TypeScript + Vite
React Three Fiber + drei (декларативная 3D-сцена, замена vanilla Three.js)
GSAP + ScrollTrigger (скролл-таймлайн камеры и анимаций, scrub + реверс)
Zustand (текущий этап, выбранный объект, sysFilter, hideVendor — стейт аналогичен
  state{} из HTML-прототипа, но управляемо)
Tailwind (2D-панели/UI поверх Canvas)
Postprocessing: @react-three/postprocessing (Bloom, Outline — аналоги UnrealBloomPass/
  OutlinePass из прототипа)
```
Сохранить принцип автодеградации качества по замеру FPS в первые секунды (см. §1) —
перенести на React-хук, управляющий пропсами постпроцессинга/pixelRatio.

Резервный вариант на случай крайне слабого оборудования на месте показа: заранее
отрендеренный видео-флайтру (cinemtic fallback), переключаемый вручную докладчиком —
не основной путь, но предусмотреть техническую возможность.

## 13. Definition of Done

- Скролл вниз/вверх плавно и реверсивно проводит через все 8 этапов сценария, с
  возможностью остановиться на любом этапе для детального клика по объектам.
- Каждый геологический слой/скважина/узел наземной инфраструктуры кликабелен, показывает
  детальную панель параметров.
- 2D-панели модулей визуально стилизованы под единую палитру, но узнаваемо повторяют
  структуру реальных UI (см. §6), с точными названиями `Nedra.*` (§5).
- Легенда/бейджи покрытия процессов по системам корректно различают ABAI (только реально
  доступные ЭМГ модули) / Nedra (донасыщение) / целевой AI-слой (§7).
- Приветственный экран — «витрина месторождения», вращение точно синхронизировано со
  скроллом, реверсивно, без интерактива.
- Работает офлайн, автодеградация качества при низком FPS, протестировано на слабом
  железе, есть кликер-фолбэк на случай проблем со скроллом на месте показа.
